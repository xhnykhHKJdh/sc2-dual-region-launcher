# 操作步骤：分开国服和欧服的安装登记

本文记录 2026 年 10 月 13 日实际完成并验证的修复流程。适用于 Windows 上 `s2_cn`、`s2` 共用一个正式服目录，而且国际产品的安装地区被记成 `cn` 的情况。

## 三按钮窗口：不用填写路径

下载仓库 ZIP 并完整解压，双击根目录的 **`星际2启动器.cmd`**，或英文入口 **`Start.cmd`**。不需要先完成下面的手动步骤，也不用填写战网或游戏路径。首次运行使用 Windows 自带的 .NET Framework 编译器和 Windows PowerShell 5.1，在本机生成 `dist\SC2Launcher.exe` 后打开 WinForms 窗口；后续复用有效构建，不需要安装 PowerShell 7 或下载第三方界面库。请保留完整文件夹，不能只移动生成的 EXE。

窗口打开时从已安装的战网登记只读识别官方启动器、国服和国际服目录，显示两服路径、版本及检查状态；空闲时每 60 秒只读刷新。保持三个主按钮，国际地区下拉框可选欧洲 `EU`、美洲 `US`、亚洲（韩台）`KR`，第二个按钮的文字随选择改变：

- **启动国服**：使用已识别的官方启动器打开 `CN / s2_cn`，随后在官方窗口完成网易登录。
- **启动欧服 / 启动美服 / 启动亚服**：使用同一套国际安装 `s2`，在已登录的官方星际页面选择实际游戏地区，核对 Play 上的地区与当前版本后启动。仍有共用 `cn` 目录冲突时拒绝启动，先用检查修复完成分离。
- **检查修复**：重新识别现状，只有符合支持条件的共用目录冲突才执行下面的完整备份修复；已经分开的安装只整理和复用桌面入口。

切换游戏地区前先正常退出当前游戏。检测到游戏或编辑器正在运行时停止启动，不强制结束进程；国际安装目录相同也不能推断当前运行的是哪个地区。

欧服、美服和亚服属于同一个国际产品 `s2`，共用分离后的国际目录，不需要为每个地区再复制一套游戏。默认的新目录名称带 ` EU`，并不限制它只能连接欧洲。国际各区档案独立；补丁发布期间可能暂时使用不同版本，按官方更新或维护提示处理，不反复删版本目录或改数据库。[官方 Global Play 说明](https://news.blizzard.com/en-gb/article/10052182/global-play-is-now-live)、[官方补丁日说明](https://news.blizzard.com/en-us/article/9623407/global-play-and-patch-day)。

战网登录地区与星际游戏地区是两项设置。本工具复用国际战网登录入口，再由本机编译的地区选择器通过 Windows UI Automation 操作官方星际页面的地区菜单，只有确认 Play 显示目标地区及匹配版本才点击。工具不会为切换国际地区改写安装元数据，官方客户端可能随后自行更新产品登记。已分离国际安装的登记地区和下载构建分支都可属于 `eu`、`us` 或 `kr`，两者不必相同；公共 Agent 与游戏内的产品登记地区仍须相同，并通过构建键和版本核对。首次需要你在官方窗口完成国际账号登录并打开《星际争霸 II》页面；界面需登录、需更新、语言或控件布局无法识别时会停止并提示手动处理，不把 `--setregion` 参数当作游戏选服成功。

上次选择的国际地区保存在 `%LOCALAPPDATA%\SC2DualRegionLauncher\preferences.json`，只含地区偏好，不记录账号、密码或验证码。

检查修复过程中会依次执行：

1. 确认是支持的共用 `cn` 目录冲突，检查游戏文件、目标目录和可用空间。
2. 退出与该安装对应的战网及 Agent。发现游戏或编辑器正在运行时，要求保存退出并停止；不会强制结束游戏。
3. 在原国服目录旁建立带 ` EU` 后缀的新目录，完整复制游戏，并核对相对文件名、数量及长度。
4. 把新 EU 副本中所有数字命名的 `Base...` 构建目录，逐个确认与原安装对应目录的文件内容散列一致，再移入私人备份。保留原国服文件、EU 的 `SC2Data` 和其他目录。
5. 备份并应用下文说明的五个安装元数据改动。只在战网已退出、配置结构可识别时，备份并开启允许多个战网实例的已知偏好；已经开启时不重写。
6. 创建或复用桌面“星际2-国服（网易）”“星际2-欧服（国际）”，把结果显示在窗口。新分离后打开官方欧服客户端供登录、校验和差异更新，只传入欧服地区，不启动游戏；窗口提示仍需完成官方更新。

在官方客户端完成校验更新后，启动器的只读刷新会重新核对两服安装。识别为已分离后，选择国际地区、点击对应启动按钮，再点击“启动国服”，分别验证国服和国际服。这样不会在刚复制的文件尚未更新时直接启动国际游戏。

已经分离且登记一致时，再次检查修复只检查安装并整理桌面入口，不复制游戏、不修改安装登记，也不结束游戏。这个分支不重写战网多开偏好；需要两个窗口时可在“设置 → App”中开启允许多个实例。

长任务在后台执行，窗口继续响应并显示进度；任务期间三个按钮和国际地区选择禁用，避免重复操作。启动或修复过程中暂时禁止关闭窗口，避免中断改动或让后台在窗口关闭后继续点击 Play；只读检查期间可以关闭。操作完成或失败后恢复相应按钮和关闭功能。发生失败时保留显示的错误和私人日志、备份；不要把这些文件上传到仓库。

操作日志保存在本机临时目录中的 `sc2-launcher-编号\activity.log`，失败时窗口会显示具体位置；成功的只读检查会清理其临时输出。日志可能包含本机路径，地区偏好也是本机私人文件；安装备份另外保存在下面的游戏旁工作目录，不能用临时日志替代恢复备份，也不要把这些私人文件上传 GitHub。

自动备份位于原游戏父目录的 `.sc2-dual-region-backups\sc2-oneclick-时间-编号` 下，窗口会显示具体路径。其中的 `operation.json` 记录进度、元数据备份位置及版本归档位置。备份可能包含本机路径和战网私人配置，请留在本机，不要上传 GitHub。

新 EU 副本是在官方欧服更新前归档复制来的程序构建。旧国际登记本身仍是 `cn`，不能用它的版本号推断未来欧服版本，也不据此比较或筛选构建。只有名字匹配 `Base` 加数字的目录会归档，其他目录不移动。官方 Agent 随后校验保留的 EU `SC2Data`，补齐真正的欧服程序文件；这一步可能多下载一些程序文件，目的在于避免旧程序被选中，并复用已复制的大量游戏数据。

打开图形窗口只读识别；点击“检查修复”才执行相应流程。原 **`开始修复.cmd`** 保留命令行一键入口，双击会直接执行同一分离流程，首次分离完成后自动打开官方欧服入口。只想在命令行查看自动识别结果，可在解压目录运行下面的只读命令：

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\scripts\Start-SC2DualRegion.ps1
```

上述入口均只对当前 PowerShell 进程使用 `ExecutionPolicy Bypass`，不更改全局执行策略。入口不会自动提权；权限不足时可以右键所用的 `.cmd` 选择“以管理员身份运行”。不要为了运行脚本更改整个盘的权限或组织策略。

如果目标 EU 目录已有未知数据、空间不足、元数据无法对应，工具会停止。复制或修复中途失败时会保留部分 EU 副本和私人进度记录，不会自动覆盖重试。保留窗口中的错误及备份，先用下面的只读诊断核对现状；不要删 `Versions`、覆盖部分副本或反复强行执行。

网易登录、验证码和账号确认由本人在官方窗口完成，窗口不采集账号或代填密码。分离后仍需要正常的官方差异更新，不能保证零下载。国服、欧服成功登录的本机修复方法已实际验证；通用脚本用合成数据测试，并在已修好的实际安装上做只读预览。

测试集共 146 项，包括 14 项隐藏 WinForms 控件测试，验证地区与按钮动作映射、任务期间关闭保护、失败恢复和临时输出清理，不操作真实战网。新图形入口的自动选服助手尚未完成真实客户端的端到端启动验证。实际手动把国际游戏地区从欧洲切到美洲时，Play 显示的版本相同；即时检查中的五个安装元数据散列尚未变化，随后官方客户端异步把产品登记地区更新为 `us`，下载构建分支仍为 `eu`，构建键和版本相同。即时快照不能证明元数据一直不变，也不能证明美服或亚服在线登录成功，或所有电脑都实际完成一键流程。

## 以下是高级手动步骤

只有需要自己选择路径、核对五文件改动或处理一键入口停止的情况，才继续下面的步骤。按自己的实际路径执行，不要照搬别人的版本号或数据库。

教程中“国服目录”是要保留的原目录，“EU 目录”是新增的国际服副本。例如：

```text
D:\game\StarCraft II       ← 原目录，保留国服
D:\game\StarCraft II EU    ← 新国际目录，欧服 / 美服 / 亚服共用
```

它们可以在同一个盘，但应是两个互不包含的普通目录。不要使用硬链接、目录联接或符号链接共用 `SC2Data`、`Versions`；两边更新必须写入各自的文件。

## 1. 先只读检查，别先卸载

脚本支持 Windows PowerShell 5.1 和 PowerShell 7。在仓库目录打开 PowerShell，使用诊断工具并指定实际路径。它是只读操作，不结束进程或修改配置：

```powershell
.\scripts\Inspect-Sc2Install.ps1 `
  -AgentDatabase 'C:\ProgramData\Battle.net\Agent\product.db' `
  -CNDirectory 'D:\game\StarCraft II' `
  -EUDirectory 'D:\game\StarCraft II EU'
```

若 PowerShell 提示禁止运行脚本，确认使用的是本仓库文件后，可在当前窗口运行 `Set-ExecutionPolicy -Scope Process -ExecutionPolicy Bypass`，再重试。这个设置只影响当前 PowerShell 进程，关闭窗口后失效；组织策略禁止执行时不要强行更改全局策略。

公共数据库通常位于：

```text
C:\ProgramData\Battle.net\Agent\product.db
```

游戏自己的数据库位于游戏根目录，文件名是隐藏文件 `.product.db`。`.build.info` 同样在游戏根目录。

查看报告中的产品 UID、安装路径、地区和版本。正常分离后的目标应类似：

| 产品 UID | 安装路径 | 安装地区 |
| --- | --- | --- |
| `s2_cn` | 原国服目录 | `cn` |
| `s2` | 新 EU 目录 | `eu` |

需要这套修复的情况是：公共数据库里的两条路径相同，且 `s2` 的安装地区为 `cn`。本次原游戏的 `.product.db` 也同时包含这两个产品。

版本号用于核对实际内容，不用于判断哪个数字“应该永远更高”。国服和国际服构建可能不同。PTR 的 UID/目录也要与正式服分清，不能把 PTR 当作 EU 副本。

若报告无法解析、缺少必需条目、一个产品出现多个不明确的登记，或路径已分开，请不要强行执行修复。保留报告，先查明具体情况。对外求助时只提供去掉个人路径的产品/地区/版本摘要，不上传整个数据库或战网日志。

## 2. 关闭更新，再准备备份

1. 退出所有正在运行的《星际争霸 II》，包括编辑器和 PTR。
2. 在两个战网窗口中退出应用；关闭窗口不一定等于退出。
3. 打开任务管理器，确认没有 `Battle.net` 和暴雪更新 `Agent.exe`。若更新正在写入，先通过战网暂停并正常退出，等 Agent 结束。
4. 确认新目录所在盘的剩余空间能容纳完整游戏副本以及后续补丁。

在游戏目录和仓库目录之外建立一个私人备份目录。至少备份以下小文件，并记录来源路径：

- 公共 `Agent\product.db`。
- 原国服目录的 `.product.db`、`.build.info`。
- 若 EU 目录已存在，其 `.product.db`、`.build.info`；原本不存在的文件也要记录为不存在。

若自己创建快捷方式或调整战网偏好，也记下原设置。工具生成的备份和 SHA-256 用于确认恢复对象，不要提交到 GitHub。本次修复只更改五个安装元数据文件，没有直接编辑 `Launcher.db` 或 `.patch.result`。

## 3. 完整复制游戏，保留原目录

把原游戏完整复制到新的 EU 目录。可以通过资源管理器复制整个文件夹；文件很大时耐心等复制完成，并核对文件数量、大小和失败提示。

要复制实际文件，包括 `SC2Data`、`Versions`、启动组件和语言数据，不能只复制 EXE。不要移动原目录，也不要删除原国服文件。复制隐藏元数据不会自动完成分服；下一步会分别重建对应的登记。

本次原游戏约 32 GB，完整复制后由官方战网校验复用已有数据，再下载缺失或不同的部分。其他机器复用多少取决于现有文件、语言包和两个地区的版本；不能保证完全零下载。

如果 EU 目录已经有一套独立且可用的安装，请不要覆盖它。先重新核对公共安装路径，可能只需要正确关联现有目录。

## 4. 预览五个元数据文件的改动

保持游戏、战网和 Agent 关闭，先运行修复工具的默认 dry-run。dry-run 只读取和预览，不修改游戏目录或公共数据库。

```powershell
.\scripts\Repair-Sc2DualRegion.ps1 `
  -AgentDatabase 'C:\ProgramData\Battle.net\Agent\product.db' `
  -CNDirectory 'D:\game\StarCraft II' `
  -EUDirectory 'D:\game\StarCraft II EU'
```

需要保存候选文件供核对时，可以另外指定 `-CandidateDirectory`，使用游戏和仓库目录之外的私人父目录。工具会在其中创建独立的 `sc2-candidates-...` 子目录。候选文件含本机路径，仅供私人检查，不要上传。

本次最终应用的登记改动如下：

| 文件 | 应做的改动 |
| --- | --- |
| 公共 `Agent\product.db` | 只调整 UID 为 `s2` 的安装目录和地区：指向新 EU 目录，地区设为 `eu`。保留该条目的原状态/版本及其他产品。 |
| 原 CN 目录 `.product.db` | 从原有多产品登记中仅移除国际 UID `s2`，保留国服 `s2_cn`。 |
| 新 EU 目录 `.product.db` | 保存重新指定路径/地区后的国际 `s2` 登记，不携带国服 `s2_cn`。 |
| 原 CN 目录 `.build.info` | 保留表头和与国服登记中 Build Key 对应的构建行。 |
| 新 EU 目录 `.build.info` | 保留表头和与原国际登记中 Build Key 对应的现有构建行，如实表示刚复制来的内容。 |

**给 EU 登记设置 `eu` 不会立即把国服文件变成欧服版本。** 本次 EU 的初始 `.build.info` 仍对应旧的 `cn` 构建；没有凭空填写欧服版本或伪造构建散列。官方 Agent 后续校验和更新，才把它替换为真正的欧服构建。

公共数据库是 protobuf 二进制数据，不要用记事本或十六进制编辑器搜索替换 `cn`、路径或版本号。本次按识别出的安装结构生成候选文件，再核对改动和散列：公共记录只更改 `s2` 的安装设置中的目录、地区；原 CN 的 `s2_cn` 和其他产品原字节保留。

这一流程只覆盖工具能确认的数据库结构。本次公共和 CN 数据库使用多条产品的封装格式，EU 文件使用单条 `ProductInstall` 格式；单条格式在本机原有 PTR 登记中也存在。工具若不能明确识别这种结构，或不能唯一对应 Build Key，应停止，不能把本案例的文件直接覆盖到别人的电脑。

核对预览时，至少确认：

- 国服仍指向原目录，国际服指向新目录。
- 国际地区改为 `eu`，没有把国服地区也改成欧服。
- 没有修改 PTR、其他暴雪游戏或账号内容。
- 目标路径互不包含，备份位于两套游戏之外。
- `.build.info` 的保留行有实际原始依据，不是按版本号猜出来的。

## 5. 应用修复，再读回核对

预览正确后，才使用修复工具的 `-Apply`。写入公共 `ProgramData` 文件可能需要管理员权限；不要为了绕过报错而修改整个盘的权限。

先替换下面的路径。`BackupDirectory` 是两套游戏和仓库目录之外的私人父目录，工具会在其中创建独立的 `sc2-backup-...` 子目录，不覆盖之前的备份：

```powershell
.\scripts\Repair-Sc2DualRegion.ps1 `
  -AgentDatabase 'C:\ProgramData\Battle.net\Agent\product.db' `
  -CNDirectory 'D:\game\StarCraft II' `
  -EUDirectory 'D:\game\StarCraft II EU' `
  -BackupDirectory 'D:\SC2-Private-Backup\metadata-before-split' `
  -Apply
```

这个高级修复工具不自动结束任何进程。应用时仍需确认战网和 Agent 已退出；应用会重新读取当前来源并生成候选，在写入前备份、核对散列。若 dry-run 后启动过战网，应重新检查预览。检测到文件在这次写入准备期间变化时应停止，不能强行应用。

记下输出中的 **`Application.BackupDirectory`**，它是这次实际生成的完整备份子目录。回滚时传这个路径，而不是命令里填写的父目录。

完成后再次运行只读诊断。公共数据库应仍有两个独立正式服产品：`s2_cn → CN 目录 / cn`，`s2 → EU 目录 / eu`。原 CN 本地登记保留 `s2_cn`，新 EU 本地登记包含 `s2`。

随后启动官方战网，不要同时手改正在被 Agent 使用的文件。

## 6. 用官方战网分别校验和更新

先用国际账号进入欧服入口，在《星际争霸 II》的游戏设置里检查安装位置确实是 EU 目录。点击更新，让官方 Agent 校验现有文件并补齐差异，等更新完成。

再用国服入口登录自己的网易/国服账号，检查安装位置仍是原 CN 目录。如战网要求更新或补齐少量文件，正常完成官方更新。无需卸载国服。

本次验证结束时：

| 产品 | 游戏版本 | 结果 |
| --- | --- | --- |
| 国服 `s2_cn` | `5.0.17.98370` | 官方更新补齐少量文件后，玩家登录成功。 |
| 欧服 `s2` | `5.0.17.98310` | 官方更新完成，并处理下述 EU 副本的版本混入后，玩家登录成功。 |

这些数字只是 2026 年 10 月 13 日的本机快照。以后应使用官方当时提供的构建，不要为了匹配本表降级或下载旧版本。

## 7. 仅在确认版本混入时处理 EU 副本

完整复制会连同国服 `Versions` 一起复制。本次欧服更新完成后，EU 副本中同时存在真正的 EU `Base98310` 和从国服复制来的 `Base98370`。启动切换器选到了更高的国服程序，结果出现安装损坏提示。

实际解决办法是：

1. 再次退出游戏、战网及 Agent。
2. 通过官方更新后的版本信息、安装登记和原 CN 目录，确认 EU 当前构建及残留目录的来源。
3. 只把 **EU 副本里的已确认国服 `Base98370`** 移到私人备份目录。
4. 保留 EU 的 `Base98310` 和其他未确认的文件，重新从官方战网进入欧服。

这次移动没有删除原国服的 `Versions\Base98370`，也没有清空 EU 的 `Versions`。两边随后均由玩家登录验证。

仓库提供版本分离工具，默认也应先预览，再明确选择要移动的目录。不要照搬 `98370`，也不要简单把所有“比某数字大”的文件夹都删除。新的构建可能正是当前地区需要的版本；只有确认是复制进来的国服构建才处理。

下面的高级维护命令针对**官方欧服更新完成后**的情况，只移动已证实与当前国服构建相同的单个残留目录。它与一键入口在**新 EU 副本、官方更新前**归档全部已核对复制构建的流程不同；不要把一键预归档流程套用到已经独立使用的欧服安装。

默认只读检查：

```powershell
.\scripts\Maintain-Sc2Versions.ps1 `
  -AgentDatabase 'C:\ProgramData\Battle.net\Agent\product.db' `
  -CNDirectory 'D:\game\StarCraft II' `
  -EUDirectory 'D:\game\StarCraft II EU'
```

工具需要国际安装登记、`.build.info` 和构建配置中的版本相互一致，同时确认候选确实对应国服构建、比国际服当前构建更高，且与 CN 原文件逐文件散列一致。单凭文件夹名称不会移动它。确认报告后，显式指定 `-MoveCopiedCNBuilds -BackupDirectory` 才执行移动；此操作不删除原 CN 的版本目录。

```powershell
.\scripts\Maintain-Sc2Versions.ps1 `
  -AgentDatabase 'C:\ProgramData\Battle.net\Agent\product.db' `
  -CNDirectory 'D:\game\StarCraft II' `
  -EUDirectory 'D:\game\StarCraft II EU' `
  -BackupDirectory 'D:\SC2-Private-Backup\eu-copied-cn-builds' `
  -MoveCopiedCNBuilds
```

这个开关会实际移动文件，不需要再加 `-Apply`。同样必须先关闭游戏、战网及 Agent。版本归档的父目录必须与 EU 游戏在同一个盘、并位于游戏目录之外；工具通过同盘移动保留文件，不执行跨盘复制后删除。

工具会在父目录下创建 `sc2-versions-archive-...` 子目录。记下输出的 **`ArchiveDirectory`** 完整路径和清单，恢复时要使用这个实际子目录。

如果没有这个现象，或无法明确确认来源，跳过本步骤。安装损坏还可能来自未完成下载、复制失败或缺失文件，可先使用战网的扫描修复。

## 8. 创建两个旧入口，或用窗口选择国际地区

推荐使用图形窗口选择国际地区；它会核对实际游戏地区后启动。下面保留高级旧快捷方式步骤：找到已安装的官方 `Battle.net Launcher.exe`，为它建立两个快捷方式。快捷方式“目标”示例：

国服：

```text
"D:\game\Battle.net\Battle.net Launcher.exe" --setregion=CN --exec="launch s2_cn"
```

国际登录入口（EU）：

```text
"D:\game\Battle.net\Battle.net Launcher.exe" --setregion=EU --exec="launch s2"
```

把路径替换成自己的实际路径，分别命名“星际2-国服（网易）”“星际2-欧服（国际）”。参数位于程序路径的引号外，前面有空格；`s2_cn` 和 `s2` 不可互换。“欧服（国际）”是保留的旧入口名称，这条参数只选择国际战网登录入口，星际游戏沿用官方客户端上次选定的地区；如果上次选择美洲，它不能保证改回欧洲。

当前案例的官方战网启动器实测接受这两个地区和产品参数。它们属于特定版本中可用的非正式启动参数，不承诺所有过去或未来的版本都支持。失效时使用战网 UI 选择地区、账号和游戏，并再次核对目录。

需要两个战网窗口时，在“设置 → App”中启用允许多个实例的选项。这样可以保留国服、国际服两个窗口；仍需每个窗口登录正确账号。网易网页认证、验证码和登录确认由你本人完成。

一键入口只在首次冲突修复且战网关闭时，处理已识别的 `Battle.net.config` 偏好 `Client.SingleInstance`：字符串 `"true"` 改为 `"false"`，先保留原配置；已为 `"false"` 时不写入。缺失或未知格式交由上述 UI 设置，不猜测字段。配置可能含私人资料，不要上传整份文件。

分别确认：

- 国服入口进入国服游戏，国际入口进入欧服正式服。
- 各自游戏设置显示正确的安装目录。
- 在游戏登录界面能正常进入自己的账号。
- 来回打开后，战网没有再把两个产品写回同一安装位置。

快捷方式不会绕过认证，也不能保证账号永久保持登录。登录失效需要重登属于正常情况。

## 9. 怎么回滚

需要恢复时先关闭游戏、战网和 Agent。使用本次修复生成的备份及清单，先预览恢复目标，再通过恢复工具实际恢复。一键入口生成的元数据备份及版本归档路径可以在其私人工作目录的 `operation.json` 中找到；以下命令同样适用，使用记录里的实际子目录。

先预览元数据恢复。以下子目录名是格式示例，请替换成修复工具输出的 `Application.BackupDirectory`：

```powershell
.\scripts\Restore-Sc2Backup.ps1 `
  -BackupDirectory 'D:\SC2-Private-Backup\metadata-before-split\sc2-backup-20261013-120000-01234567'
```

校验通过后才实际恢复：

```powershell
.\scripts\Restore-Sc2Backup.ps1 `
  -BackupDirectory 'D:\SC2-Private-Backup\metadata-before-split\sc2-backup-20261013-120000-01234567' `
  -Apply
```

恢复工具只接受仍与该次原始文件或候选文件散列匹配的当前文件。**官方更新完成后，文件通常已经变化，工具会拒绝覆盖。** 此时不要绕过校验强行恢复旧数据库；保存当前状态，重新诊断并通过官方战网关联、校验正确目录，必要时请能检查这份元数据的人评估。

如果先前归档了 EU 副本里的构建目录，需要另行恢复。把 `ArchiveDirectory` 换成版本维护工具输出的实际档案目录，或一键入口 `operation.json` 中的 `VersionsArchiveDirectory`：

```powershell
.\scripts\Maintain-Sc2Versions.ps1 `
  -RestoreArchive `
  -ArchiveDirectory 'D:\SC2-Private-Backup\eu-copied-cn-builds\sc2-versions-archive-20261013-120000-01234567'
```

`-RestoreArchive` 会实际移回文件，不另加 `-Apply`；档案来源和原路径冲突时应停止，不覆盖后来出现的新文件。

一键入口的预更新归档清单使用 `Mode=NewEUCopyBeforeOfficialUpdate`，可能含多个 `Moves`。恢复工具只允许把这些通过校验的目录恢复到清单记录的原新 EU 副本路径；有同名新构建、散列变化或路径不一致时拒绝恢复。普通更新后维护档案仍只接受单个已确认国服构建。

恢复时遵循这些原则：

1. 保存修复后新生成的元数据副本，避免丢失后续状态。
2. 按备份清单和校验结果恢复对应的五个元数据文件；修复前不存在的 EU 文件按清单处理，不能拿别的机器的数据库代替。
3. 若归档过 EU 副本的 `Base...`，只用本次档案和清单恢复到**原 EU 路径**；原位置出现新文件时先核对，不能覆盖新构建。
4. 再次诊断并检查路径，再启动官方战网。

恢复元数据不会撤销战网随后已经更新的游戏文件；官方战网可能重新校验或下载差异。旧备份也可能包含旧安装路径。恢复公共数据库会同时恢复其记录的其他产品状态，因此优先使用紧邻本次修复的备份，并确认此后没有其他游戏安装变化。

国服原始游戏数据一直保留。暂时不要删除 EU 副本和备份，等两个地区都稳定使用、确认不需要回滚后，再自行整理。

## 常见误会

**一定要分 C 盘和 D 盘吗？**

不需要。本次两套正式服都在 D 盘。目录和产品登记必须分开；把战网装在另一个盘本身不会隔离共用的 `ProgramData` 或用户配置。

**能不能只改战网地区？**

地区参数可以选择登录入口，但不能保证纠正已经错误的安装路径和产品登记，也不能替代星际页面的游戏地区选择。修改后仍要检查 `s2` 指向的目录及实际游戏构建。本项目图形入口会另行操作并确认官方星际页面的游戏地区。

**欧服、美服、亚服要分别下载吗？**

它们共用一个国际安装 `s2`，本方案只保留国服与国际服两套目录。各区账号档案和服务器进度仍独立，补丁发布期间也可能存在短暂版本差异；选择目标区后遵循官方更新与维护提示。

**“Use a Different Folder”能一键转换吗？**

它用于关联安装目录。如果自己的安装登记正常，优先通过官方 UI 关联现有安装。本文处理的是已经混在一起的登记；不能保证这个按钮同时修复地区、产品和构建信息。

**两个版本是不是共用存档和偏好？**

本方案分离安装数据，`Documents\StarCraft II` 中的用户文件仍可能共用。账号的服务器进度以各地区服务为准；本文不做个人文档目录或账号迁移。

**以后是不是完全不用下载？**

仍需正常官方补丁、校验修复和语言包下载。目标是停止国服、国际服反复覆盖同一安装，复用这次已有数据；不是冻结版本。
