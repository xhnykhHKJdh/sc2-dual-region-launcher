# 星际争霸 II：国服 / 国际服三按钮启动器

双击打开窗口，用 **启动国服、启动国际服、检查修复** 三个主按钮操作，自动识别安装路径，不用手填。国际地区下拉框可选 **欧服、美服、亚服（韩台）**，第二个按钮随选择显示“启动欧服”“启动美服”或“启动亚服”。窗口打开时只读取安装情况，显示国服和国际服目录、版本和状态；空闲时每 60 秒只读刷新，不会因为打开窗口就修改安装。

这份教程和 PowerShell 工具解决一个具体问题：Windows 战网把国服 `s2_cn` 和国际服 `s2` 登记到同一个《星际争霸 II》目录，国际服的安装地区还被记成 `cn`。登录欧服后，战网继续使用国服文件，切回来又修补或重新下载。

做法是保留国服目录，把已有游戏完整复制为独立的国际服目录，修正两边的安装登记，再让官方战网各自校验、补齐对应版本。**两套游戏可以在同一个盘，关键是目录和安装登记分开。** 欧服、美服和亚服共用国际产品 `s2` 及同一国际安装目录，无需再复制成三套；分离时建立的目录即使名称带 ` EU`，也可以给这三个国际地区使用。

这是一个已验证案例的社区修复方案。修改 Battle.net 安装数据库不是暴雪或网易的官方维修流程；数据库格式和启动参数将来可能变化。一键入口会先识别安装情况，只有符合支持条件时才执行。

## 先看自己是否适用

工具会自行检查，自动分离的目录冲突须满足以下条件：

- 使用 Windows，需要保留国服和国际服两个账号的正常登录入口。
- 公共 `Agent\product.db` 中存在 `s2_cn` 和 `s2`。
- 两个产品的安装路径指向同一个正式服游戏目录。
- 国际产品 `s2` 的安装地区为 `cn`，而你希望它使用欧服。
- 原目录中存在对应的安装元数据和完整游戏数据，且有空间再存一份游戏。

只有“更新慢”“显示安装”或“无法登录”，不能直接认定是这个问题。若安装已经分开且登记一致，工具会检查并整理桌面入口；若没有 `s2_cn`、数据库无法解析，或错误来自网络/账号认证，则需要先处理对应原因。

`StarCraft II Public Test` / PTR 是测试服，不能当作欧服正式客户端。

## 怎么使用

**下载 ZIP、解压，双击 `星际2启动器.cmd`，不用填写任何路径。** 英文入口 `Start.cmd` 打开同一个窗口。首次运行用 Windows 自带的 .NET Framework 编译器和 Windows PowerShell 5.1，在本机生成 `dist\SC2Launcher.exe`，随后打开 WinForms 窗口；以后复用有效的本机构建。不下载第三方依赖，命令行工具也支持 PowerShell 7。请保留完整的解压目录，不能只拿走生成的 EXE。

1. 在 GitHub 页面点 **Code → Download ZIP**，把 ZIP 完整解压到一个普通文件夹。
2. 双击 `星际2启动器.cmd`，查看自动识别的目录、版本和状态。
3. 若已经分开，点击 **启动国服**；国际服先在下拉框选欧服、美服或亚服，再点击对应启动按钮。首次需在官方国际战网完成登录并打开《星际争霸 II》页面。若提示共用目录冲突，先保存并退出星际游戏、编辑器和 PTR，再点 **检查修复**。
4. 修复会先检查空间，再退出相关战网和 Agent、复制游戏、保留备份并分离安装登记。窗口会显示进度，长任务在后台运行；任务期间按钮和地区选择暂停使用，启动或修复过程中暂时不能关闭窗口，等待完成或失败结果。
5. 新分离完成后，会打开官方欧服战网客户端，并提示完成校验更新；这一步不启动游戏。在官方窗口登录并正常完成差异补丁，启动器刷新为已分离状态后，选择国际游戏地区并启动；再点击 **启动国服**，确认国服与国际服都能进入游戏。

| 按钮 | 行为 |
| --- | --- |
| **启动国服** | 使用识别到的官方启动器打开 `CN / s2_cn`；仍需正常网易登录。 |
| **启动欧服 / 启动美服 / 启动亚服** | 共用国际产品 `s2`；在官方星际页面选择并确认实际游戏地区，再点击 Play。共用目录冲突尚未修复时拒绝启动。 |
| **检查修复** | 重新检查安装；对支持的目录冲突执行备份和分离，新分离后打开官方欧服客户端供校验更新；已经分开时整理并复用桌面入口。 |

首次分离需要完整复制一份游戏，耗时取决于磁盘。自动备份保存在原游戏旁的 `.sc2-dual-region-backups` 目录，窗口会显示具体位置。工具会把新 EU 副本中从原安装复制来的所有 `Base数字` 构建目录逐个核对内容散列，再移入备份，不根据旧登记猜测这些程序属于哪个地区。原国服文件、EU 的 `SC2Data` 和其他目录保留，官方 Agent 随后补齐对应的欧服程序文件。可能需要多下载一些程序文件，但已有的大量游戏数据仍用于校验复用。

**已经分离成功时，检查修复只检查安装并补齐或复用正确的桌面入口，不重新复制游戏或修改安装登记。** 首次分离遇到目标副本已有未知文件、空间不足或游戏仍在运行时会停止；不符合支持条件也会停止，不盲目覆盖。若中途停止，保留窗口中的错误信息、私人日志、备份及部分 EU 副本，按[详细步骤](docs/manual-repair.md)检查后再处理。这些私人文件不要上传 GitHub。

网易账号登录、验证码及官方登录确认需要本人完成。正常官方补丁、语言包和缺失文件仍会下载。

国际战网的**登录地区**与星际页面的**游戏地区**是两项设置。本工具复用国际战网登录入口，再通过 Windows UI Automation 操作已登录的官方星际页面，核对 Play 显示的目标地区和当前版本后才启动游戏；工具不会通过改写安装登记来选区。官方客户端切换地区后可能异步更新安装登记。已分离国际安装的登记地区和下载构建分支都可属于 `eu`、`us` 或 `kr`，两者不必相同；公共 Agent 与游戏内的产品登记地区仍须相同，并通过构建键和版本核对。仅修改 `--setregion` 不会被当作选服成功。若需要登录、正在更新，或界面语言/布局无法明确识别，会停止并提示你在官方窗口处理，不绕过认证。

国际地区选择会记在本机 `%LOCALAPPDATA%\SC2DualRegionLauncher\preferences.json`，下次打开沿用；只记录地区，不保存账号或密码。国际各区档案独立，补丁发布期间可能短暂存在地区版本差异；遇到这种情况按官方提示更新或等待对应地区维护完成，不反复修改安装登记。[官方 Global Play 说明](https://news.blizzard.com/en-gb/article/10052182/global-play-is-now-live)、[官方补丁日说明](https://news.blizzard.com/en-us/article/9623407/global-play-and-patch-day)。

切换游戏地区前先正常退出当前游戏。检测到游戏已经运行时，工具不会强行结束它，也不会重复启动同一个游戏。

只想自动识别并查看情况，可在解压目录打开 PowerShell，运行下面这条**只读预览**，同样不用填写路径：

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\scripts\Start-SC2DualRegion.ps1
```

原入口 **`开始修复.cmd`** 保留为命令行一键修复：它会传入 `-Run`，直接执行分离流程，首次分离成功后打开官方欧服入口。`星际2启动器.cmd` 和 `Start.cmd` 打开图形窗口，等待你选择按钮。`ExecutionPolicy Bypass` 只对这一次 PowerShell 进程有效，不修改全局执行策略。若系统提示权限不足，可对所用 `.cmd` 选择“以管理员身份运行”；不要修改整个盘的权限或覆盖不明安装。

需要自行指定目录、查看五文件修复细节或回滚时，使用[高级手动步骤](docs/manual-repair.md)。

| 工具 | 用途 |
| --- | --- |
| `星际2启动器.cmd` / `Start.cmd` | 打开三按钮窗口，自动识别目录、版本和状态。 |

| `scripts/Show-SC2Launcher.ps1` | Windows PowerShell 5.1 图形界面，启动时只读识别。 |

| `scripts/Inspect-Sc2Install.ps1` | 只读查看安装登记和构建信息。 |

## 修好后怎么打开

平时推荐使用图形窗口：选国际地区，再点击对应按钮，工具会核对实际游戏地区。检查修复仍生成国服、国际服两个旧桌面入口；其中“欧服（国际）”快捷方式只选择国际战网登录入口，游戏沿用官方客户端上次选定的地区，不能保证是欧洲。下面仅说明旧入口参数，供高级手动创建时核对；程序应指向**已安装的官方** `Battle.net Launcher.exe`。

国服：

```text
"D:\game\Battle.net\Battle.net Launcher.exe" --setregion=CN --exec="launch s2_cn"
```

国际登录入口（EU）：

```text
"D:\game\Battle.net\Battle.net Launcher.exe" --setregion=EU --exec="launch s2"
```

当前案例的战网版本实测支持这些参数，但它们没有面向所有版本的正式支持保证。若参数失效，使用战网登录界面的地区选择和游戏页面进入游戏，并检查两边仍指向正确目录。

首次修复关闭战网后，工具会备份并调整可识别的“允许多个实例”偏好；已经启用时不重写。若偏好格式无法识别，或安装原本已分开，请在战网“设置 → App”中启用允许多个实例。登录过期时重新登录属于正常情况；快捷方式不保存或代填密码。

## 已验证的结果

2026 年 10 月 13 日，在一台 Windows 电脑上完成以下分离，并由玩家确认国服、欧服都能登录：

| 产品 | 独立目录示例 | 验证时版本 |
| --- | --- | --- |
| 国服 `s2_cn` | `D:\game\StarCraft II` | `5.0.17.98370` |
| 欧服 `s2` | `D:\game\StarCraft II EU` | `5.0.17.98310` |

这些版本号只是这次验证的快照，**不是执行条件，也不要写死为目标版本**。本次欧服复用了原游戏的大量数据，由战网下载差异；移出 EU 副本中残留的国服 `Base98370` 后，欧服正常进入。国服经官方更新补齐少量文件后也正常进入。

验证分为两部分：这台电脑的实际修复方法和国服、欧服登录已验证；仓库的通用脚本用合成数据测试，并在已修好的实际安装上做只读预览。测试集共 146 项：44 项核心修复、30 项一键流程、58 项启动控制及地区解析、14 项隐藏 WinForms 控件测试。窗口测试使用模拟任务验证按钮、地区选择、关闭保护、失败重试和临时文件清理，不启动真实战网或游戏。

新图形入口的自动选服助手尚未完成真实官方客户端的端到端启动验证，模拟测试不等于账号登录成功。实际手动把国际游戏地区从欧洲切到美洲时，Play 显示的版本相同；即时检查中的五个安装元数据散列尚未变化，随后官方客户端异步把产品登记地区更新为 `us`，下载构建分支仍为 `eu`，构建键和版本相同。因此即时快照不代表安装元数据会一直不变。这项界面检查也不等于完成美服或亚服的在线登录。未在所有电脑上完成一键流程的实际登录测试。

两套 `SC2Data` 和 `Versions` 独立保存，不使用链接共享安装数据。Windows 用户的 `Documents\StarCraft II` 偏好和个人文件仍可能共用；本方案不隔离该目录。官方正常补丁、语言包和缺失文件仍会下载。

## 项目范围

- 只处理这个已识别的安装登记冲突，不修改游戏或战网的 EXE，不绕过登录或认证。
- 图形窗口打开时只读识别；检查修复先识别和检查，再关闭相关战网和 Agent、备份后执行，不会强制结束正在运行的游戏。高级修复工具默认只预览，实际写入需要 `-Apply`。
- 不支持盲目替换二进制字符串。工具按当前可识别的 protobuf 结构处理；识别失败、重复条目或构建对应不清楚时应停止。
- 新 EU 副本的已核对复制构建，以及更新后已确认混入的构建，只移动到私人备份；不要每次切服都删除 `Versions`。
- 仓库只发布文档、源代码及合成测试，不发布真实游戏文件、截图、日志、数据库、账号资料或备份。
